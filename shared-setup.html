Step 3

Upload the prepared update

  1. Back up your existing GitHub website first. Download and extract JCRGM-Upload-Ready-Update.zip.
  2. In your jcrgm-app repository, open the folder currently publishing index.html.
  3. Choose Add file → Upload files. Upload the extracted files and directories into that same folder. Preserve vendor/ and licenses/ as folders. Do not upload the ZIP itself or add an extra containing folder.
  4. Replace the matching update files, but keep all your other church pages and assets. Commit the upload and wait for GitHub Pages to finish deploying.
  5. Open your Announcements page. If the installed app shows the old pages, close/reopen it and reload.

The public connection settings are already filled in. Do not use an older, unconfigured ZIP.

The updated service worker retains the public offline-start assets from your current worker while using network-first updates. Cloud and authentication responses are never cached. A public manifest file is the only JSON caching exception. Shared checklists still need internet access.

Step 4

Activate your first leader account

  1. On the published Announcements page, choose Member / leader sign in → Request access.
  2. Create your church-app account, confirm its email and sign in. This is separate from your Supabase dashboard login; it can use the same email. Your church-app account will initially be pending.
  3. Enter that exact confirmed email below and click Prepare leader script.
  4. Copy the resulting script into a new Supabase SQL Editor query and click Run.
  5. Refresh Announcements. You can now publish notices and use Manage member access.

No email is sent by this form. The script is generated locally in your browser.

Only your Supabase project owner account can execute this script. The first person to register is not automatically made a leader. Do not upload your personalised leader script to GitHub.

Step 5

Publish and check on a second device

  1. As leader, open programme preparations, choose New programme or import an old local plan, then click Publish changes.
  2. Create a second account, approve it as a member in Announcements → Manage member access, and open the same programme on another device. It should be read-only.
  3. Create an announcement and enable Publish publicly. Confirm it appears in a signed-out browser, while checklists still require approved membership.
  4. Keep a notice as a draft and a private follow-up record. Verify neither is visible to signed-out visitors, and the private record is also unavailable to members.
Members can see shared task titles, owners, notes, programme details and safe team assignments. Keep confidential contact, pastoral and financial information out of those shared fields. Private registers are leader-only.

Updates refresh while the page is open and online, using real-time signals and polling. No SMS, WhatsApp or closed-app push notifications are included. Revocation cannot retrieve anything already printed, downloaded or copied.
